# OS 实验报告写作风格

## 总体结构

- 标题使用 `# <center>LabX 标题</center>` 或简洁的 `# labX`。
- 主体按 `## PartN` 或 `## AssignmentN` 组织；小任务按 `### N.M` 展开。
- 开头可放一句实验环境，例如 `> 实验环境：Ubuntu 22.04 (x86_64 / WSL2)`。
- 若有大模型辅助，保留说明，例如 `**本次实验部分代码和注释参考自大模型。**`

## 单个小节模板

````markdown
### N.M 小节标题

简述本小节要完成的任务。

**实现思路：** 说明采用的方法、关键数据结构、关键寄存器或核心流程。

```bash
# 关键命令，或替换为 asm/cpp/text
make run
```

![运行截图](待补充截图路径)

**结果分析：** 根据截图、终端输出或调试结果解释为什么说明实验成功。
````

## 常见段落类型

- **复现类小节**：写清楚复现对象、改动点、命令、截图和复现是否成功。
- **实现类小节**：先写设计目标，再写关键代码或伪代码，最后解释运行结果。
- **对比类小节**：固定输入或测试线程，分别展示两种方案的输出，再比较优缺点。
- **思考题**：直接回答问题；需要推导时列公式、代入过程和最终十六进制结果。
- **问题解决**：使用 `现象`、`原因`、`解决` 三段，避免泛泛而谈。

## 证据写法

- 截图用于证明图形界面、QEMU 启动、GDB 断点、monitor 验证或 VGA 输出。
- 终端长输出用 `text` 代码块；保留能支持结论的关键行，不必贴满无关日志。
- 结果分析必须绑定证据，例如地址变化、寄存器状态、线程输出顺序、页表映射关系。
- 不要编造截图路径、输出内容、内存地址或调试结果；缺证据时明确写 `待补充`。

## 语气和格式

- 使用中文技术报告语气，直接、具体、以实验现象为中心。
- 保留必要英文术语：`QEMU`、`GDB`、`MBR`、`GDT`、`IDT`、`PDE`、`PTE`、`MESA`。
- 对核心机制使用加粗标签，例如 `**核心机制分析：**`、`**设计要点：**`。
- 代码块外只解释关键逻辑；不要把完整项目代码搬进报告，除非用户要求。
