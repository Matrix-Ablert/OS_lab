#### 1.1.1 `waitReady()` — 等待磁盘就绪

**实现思路：** `DiskDriver::waitReady()` 通过轮询 ATA 状态寄存器 `0x1F7` 判断磁盘是否忙碌：

```cpp
void DiskDriver::waitReady()
{
    uint8 status;
    do
    {
        asm_in_port(ATA_STATUS, &status);
    } while (status & ATA_STATUS_BSY);
}
```

`ATA_STATUS_BSY` 的值为 `0x80`，对应状态寄存器的 BSY 位。当该位为 1 时，表示磁盘仍在处理上一条命令，此时不能继续设置 LBA 或发送读写命令。循环直到 BSY 位清零，表示磁盘空闲，方可进行后续操作。

#### 1.1.2 `selectSector()` — 设置 LBA 地址和扇区数

**实现思路：** `selectSector(uint32 lba, uint8 count)` 负责选择要访问的扇区：

```cpp
asm_out_port(ATA_SECT_CNT, count);
asm_out_port(ATA_LBA_LOW,  (uint8)(lba & 0xFF));
asm_out_port(ATA_LBA_MID,  (uint8)((lba >> 8) & 0xFF));
asm_out_port(ATA_LBA_HIGH, (uint8)((lba >> 16) & 0xFF));
asm_out_port(ATA_DRIVE_HEAD, (uint8)(0xE0 | ((lba >> 24) & 0x0F)));
```

流程为：
1. 先调用 `waitReady()` 等待磁盘空闲。
2. 向端口 `0x1F2` 写入扇区数量 `count`。
3. 分别向 `0x1F3`、`0x1F4`、`0x1F5` 写入 LBA 地址的低、中、高 8 位。
4. 向端口 `0x1F6` 写入 `0xE0 | LBA[27:24]`，选择主盘（Master Drive）并启用 LBA 寻址模式。

#### 1.1.3 `readSectors()` — 读取扇区

**实现思路：** `readSectors()` 对每个扇区重复执行一次 ATA PIO 读取：

1. 调用 `selectSector(lba + s, 1)` 选择当前扇区。
2. 向命令寄存器 `0x1F7` 写入 READ 命令 `0x20`。
3. 轮询 `0x1F7` 状态寄存器，直到 DRQ 位 `0x08` 置 1，表示数据已准备好。
4. 从数据寄存器 `0x1F0` 连续读取 256 个 16-bit word（512 字节 = 1 扇区）。

一个扇区大小为 512 字节，`512 / 2 = 256`，所以每个扇区需要执行 256 次 16 位端口读取操作。

#### 1.1.4 `writeSectors()` — 写入扇区

**实现思路：** `writeSectors()` 与读取流程类似，区别在于命令和数据方向：

1. 调用 `selectSector(lba + s, 1)` 选择当前扇区。
2. 向 `0x1F7` 写入 WRITE 命令 `0x30`。
3. 等待 DRQ 位置 1。
4. 将缓冲区中 256 个 16-bit word 依次通过 `asm_out_port_word(0x1F0, ...)` 写入磁盘数据寄存器。

**异同对比：**

| 项目 | `readSectors()` | `writeSectors()` |
|:---|:---|:---|
| ATA 命令 | `0x20` (READ SECTORS) | `0x30` (WRITE SECTORS) |
| 数据方向 | 磁盘 → 内存 (`in ax, dx`) | 内存 → 磁盘 (`out dx, ax`) |
| 前置流程 | 相同：selectSector → 发命令 → 等 DRQ | 相同 |
| 端口 | 同为 `0x1F0`（数据）、`0x1F7`（命令/状态） | 相同 |

#### 1.1.5 为什么 `0x1F0` 使用 16 位 I/O？

**核心分析：** ATA 数据寄存器 `0x1F0` 是 16 位数据端口，PIO 数据传输的基本单位是 16-bit word，而非 8-bit byte。若使用 `in al, dx` 或 `out dx, al`，每次只能传输 1 字节，不符合 ATA 数据端口的传输宽度，也会破坏扇区数据读取和写入的节奏。本实验新增了 `in ax, dx` 和 `out dx, ax` 汇编内联函数，每次传输 2 字节，正好完成一个 ATA word 的读写。

#### 1.1.6 输出验证与分析

结合以上实现思路，对 `Assignment1/output.txt` 的实际输出逐项验证：

**（1）空文件不分配数据簇：** Step 4 中 `hello.txt`、`data.bin`、`readme` 三个文件在创建后的 CLUSTER 列均为 `0`。这与 `createFile()` 只初始化目录项、不调用 `allocateCluster()` 的实现一致——空文件的 `firstCluster` 保持为 `0`，后续首次写入时才会分配簇。

**（2）簇顺序分配策略：** Step 6 中写入后三个文件的簇号分别为 `hello.txt(2)`、`readme(3)`、`data.bin(4)`。注意写入顺序是 hello.txt → readme → data.bin，但簇号并未严格按写入顺序排列（readme 的簇 3 先于 data.bin 的簇 4）。这说明 `allocateCluster()` 从簇 2 开始扫描 FAT 表取第一个 `FAT16_FREE` 条目，分配顺序与 `findEntry()` 返回的目录项索引无关——只要写入前三个文件均无预分配簇，它们获得簇号 2、3、4 的排列是自然顺序。

**（4）覆盖写不产生簇泄漏：** Step 11 覆盖写 `hello.txt` 后，Step 12 的 Used clusters 仍为 `2`（与 Step 9 删除 data.bin 后相同）。`writeFile()` 覆盖写时的流程为：`freeClusterChain()` 释放旧簇 → 重新 `allocateCluster()` 分配新簇 → 写入数据。旧簇链被正确释放且重新利用，簇数与文件数量保持一致，无泄漏。

**（5）总体一致性：** 整个 Demo 的簇数变化轨迹为：格式化后 Used = 0 → 写入 3 文件后 Used = 3 → 删除 1 文件后 Used = 2 → 覆盖写后 Used = 2。每一步簇数变化与文件操作严格对应，FAT 表与目录项始终保持一致。

### 1.2 FAT16 文件系统布局分析

#### 1.2.1 磁盘完整布局

本实验的文件系统从磁盘扇区 `500` 开始，前面的扇区留给 MBR、Bootloader 和 Kernel。

| 区域 | 起始扇区 | 结束扇区 | 大小 | 说明 |
|:---|:---:|:---:|:---:|:---|
| MBR | 0 | 0 | 1 扇区 | 主引导记录 |
| Bootloader | 1 | 5 | 5 扇区 | 引导加载器 |
| Kernel | 6 | 150 | 145 扇区 | 内核镜像写入区域 |
| 保留空间 | 151 | 499 | 349 扇区 | 避免覆盖内核和引导区域 |
| **SuperBlock** | **500** | **500** | 1 扇区 | 简化 BPB，魔数为 `SF16` |
| **FAT 表** | **501** | **532** | 32 扇区 | 每项 2 字节，共 8192 项 |
| **根目录区** | **533** | **564** | 32 扇区 | 每项 32 字节，最多 512 项 |
| **数据区** | **565** | 后续 | 8190 个可用簇 | 文件内容区，1 簇 = 1 扇区 |

对应代码常量：

```cpp
#define FS_START_SECTOR   500
#define FAT_SECTORS       32
#define ROOT_DIR_SECTORS  32
#define FAT_ENTRIES       8192
#define DATA_START_OFFSET 65
#define SECTOR_SIZE       512
```

其中 `DATA_START_OFFSET = 1 + FAT_SECTORS + ROOT_DIR_SECTORS = 1 + 32 + 32 = 65`，所以数据区起始扇区为 `500 + 65 = 565`。

#### 1.2.2 FAT 表容量

FAT16 表中每个条目占 **2 字节**。FAT 表共 32 个扇区，每扇区 512 字节：

```
每扇区 FAT 条目数 = 512 / 2 = 256
FAT 条目总数 = 32 × 256 = 8192
```

FAT 条目 0 和 1 是保留条目，不对应实际数据簇；有效数据簇从 2 开始。因此最多可管理：

```
8192 - 2 = 8190 个数据簇
```

本实验中 1 簇 = 1 扇区 = 512 字节，数据区最大可用容量约为 `8190 × 512 = 4193280 字节 ≈ 4 MB`。

#### 1.2.3 根目录容量

根目录区占 32 个扇区，每个目录条目大小为 32 字节：

```
每扇区目录条目数 = 512 / 32 = 16
根目录最大条目数 = 32 × 16 = 512
```

根目录最多可存放 **512 个文件或目录项**（本 Assignment 只实现单级根目录）。

#### 1.2.4 FAT 链示例

若一个文件占用的簇链为 `5 → 8 → 12 → EOF`，则 FAT 表中的值为：

```
FAT[5]  = 8
FAT[8]  = 12
FAT[12] = 0xFFF8     (FAT16_EOF)
```

其中 `0xFFF8` 是本实验定义的 `FAT16_EOF`，表示文件结束。

#### 1.2.5 `clusterToSector()` 计算逻辑

```cpp
uint32 FAT16::clusterToSector(uint16 cluster)
{
    return FS_START_SECTOR + DATA_START_OFFSET + (cluster - 2);
}
```

计算公式含义：

- `FS_START_SECTOR = 500`：文件系统起始扇区。
- `DATA_START_OFFSET = 65`：数据区相对文件系统起始位置的偏移（1 SB + 32 FAT + 32 根目录）。
- `cluster - 2`：FAT 约定簇号 0 和 1 保留，簇 2 才是第一个有效数据簇。

示例映射：
```
cluster 2 → sector = 500 + 65 + 0 = 565
cluster 3 → sector = 500 + 65 + 1 = 566
cluster 4 → sector = 500 + 65 + 2 = 567
```

### 2.1 文件创建与写入

#### 2.1.1 `createFile("hello.txt")` 执行流程

**实现思路：**

`createFile()` 首先检查文件系统是否已挂载（`mounted == false` 则直接返回错误）。随后调用 `findEntry(name)` 检查同名文件是否已存在。

**`toFAT16Name` 转换过程：** `findEntry()` 内部会先将普通文件名转换为 FAT16 的 8.3 格式。以 `hello.txt` 为例：

```
输入文件名: hello.txt
转换后: "HELLO   TXT" （8 字节主文件名 + 3 字节扩展名 = 11 字节）
```

转换规则：
1. 先把 11 字节目标缓冲区全部填为空格 `0x20`。
2. 点号前最多复制 8 个字符作为主文件名。
3. 小写字母转换为大写字母。
4. 点号后最多复制 3 个字符作为扩展名。
5. 点号本身不存入目录项。

**查找空闲目录项（`findFreeEntry()`）：**

如果无同名文件，调用 `findFreeEntry()` 查找空闲根目录项，空闲条件为：

```cpp
entry.filename[0] == 0x00      // 从该项开始后续都未使用
entry.filename[0] == ATTR_DELETED  // 该项曾被删除(0xE5)，可复用
```

**目录条目初始化：** 找到空闲项后，初始化一个 `DirEntry`：

| 字段 | 值 | 说明 |
|:---|:---|:---|
| `filename[8]` | `"HELLO   "` | 8 字节主文件名 |
| `extension[3]` | `"TXT"` | 3 字节扩展名 |
| `attributes` | `ATTR_ARCHIVE` | 标记为普通文件 |
| `firstCluster` | `0` | 空文件暂不占用数据簇 |
| `fileSize` | `0` | 文件大小为 0 |

最后调用 `writeDirEntry(idx, &entry)` 将目录项写回根目录区。

#### 2.1.2 `writeFile("hello.txt", data, size)` 执行流程

**实现思路：** `writeFile()` 是覆盖写模式，主要步骤如下：

**第一步 — 查找/创建目录项：** 若文件已存在则读取旧目录项，不存在则类似 `createFile()` 创建新目录项。

**第二步 — 释放旧簇链（覆盖写关键）：** 若文件已有数据簇：

```cpp
if (entry.firstCluster >= 2)
{
    freeClusterChain(entry.firstCluster);
}
```

`freeClusterChain()` 从起始簇开始沿 FAT 表遍历，把每个簇的 FAT 条目改为 `FAT16_FREE`，直到遇到 EOF 或无效簇号。

**第三步 — 计算所需簇数：**

```cpp
clustersNeeded = (size + SECTOR_SIZE - 1) / SECTOR_SIZE;
```

向上取整，例如 `size = 513` 需要 2 个簇。

**第四步 — 分配簇（`allocateCluster()`）：** 从簇 2 开始扫描 FAT 表，找到第一个值为 `FAT16_FREE` 的条目，标记为 `FAT16_EOF` 并返回簇号。簇 0 和簇 1 保留，不会分配给文件。

**第五步 — 构建 FAT 链：** 每分配一个新簇：
- 第一个簇记录为 `firstCluster`。
- 从第二个簇开始，把上一个簇的 FAT 条目改为当前簇号。
- 最后一个簇的 FAT 条目保持 `FAT16_EOF`（`0xFFF8`）。

**第六步 — 写入数据：** 将数据分块复制到 512 字节扇区缓冲区，再通过 `disk->writeSectors()` 写入对应扇区。

**第七步 — 更新目录项并同步 FAT：**
```cpp
entry.firstCluster = firstCluster;
entry.fileSize = size;
writeDirEntry(idx, &entry);
syncFAT();   // 必须！否则内存修改不会持久化到磁盘
```

**为什么必须调用 `syncFAT()`？** FAT 表先在内存数组 `fatTable` 中修改。若不写回磁盘，重启或重新挂载后磁盘上的 FAT 表仍是旧状态，文件簇链会丢失或不一致。

### 2.2 文件读取与删除

#### 2.2.1 `readFile("hello.txt", buffer, maxSize)` 执行流程

**实现思路：**

`readFile()` 首先通过 `findEntry(name)` 查找目录项，从中获取两个关键字段：
- `entry.firstCluster`：文件数据的第一个簇号。
- `entry.fileSize`：文件真实字节数。

然后计算实际读取量：
```cpp
readSize = entry.fileSize;
if (readSize > maxSize)
    readSize = maxSize;
```

随后从 `firstCluster` 开始沿 FAT 链逐簇读取：
1. 调用 `clusterToSector(cluster)` 把簇号转为扇区号。
2. 调用 `disk->readSectors(...)` 读取该簇对应扇区。
3. 将需要的字节复制到用户缓冲区。
4. 通过 `cluster = fatTable[cluster]` 跳到下一个簇。

**停止条件：**
- 当前簇号进入 EOF 区间（`cluster >= FAT16_BAD`）。
- 已读取字节数达到 `readSize`（文件大小或 `maxSize`）。

#### 2.2.2 `deleteFile("data.bin")` 执行流程

**实现思路：**

1. 通过 `findEntry(name)` 查找目录项，找不到则返回失败。
2. 若文件有数据簇，调用 `freeClusterChain(entry.firstCluster)` 释放所有簇，将这些簇标记为 `FAT16_FREE`。
3. 调用 `syncFAT()` 将修改后的 FAT 表写回磁盘。
4. 将目录项首字节设为 `0xE5`（`ATTR_DELETED`）：

```cpp
entry.filename[0] = (char)ATTR_DELETED;
writeDirEntry(idx, &entry);
```

后续 `listFiles()` 和 `findEntry()` 会跳过首字节为 `0xE5` 的目录项，而 `findFreeEntry()` 可以重新使用该位置。

**删除后数据是否真的从磁盘上擦除了？** 没有。删除操作只做了两件事：
1. FAT 表中对应簇被标记为空闲。
2. 目录项首字节被标记为 `0xE5`。

数据区的原始字节仍然留在磁盘上，直到这些簇被新文件重新分配并覆盖写入。因此 FAT 文件系统中删除文件存在数据恢复可能；若需要安全删除，必须主动覆盖原数据簇。

### 3.1 文件追加写入 (`appendFile`)

**接口定义：**

```cpp
bool FAT16::appendFile(const char *name, const char *data, uint32 size);
```

**实现思路：**

**文件不存在时：** 直接调用 `writeFile(name, data, size)`，行为与普通写入一致。

**文件已存在时：** 读取目录项获取 `firstCluster` 和 `fileSize`，然后沿 FAT 链找到最后一个簇：

```cpp
while (fatTable[lastCluster] >= 2 && fatTable[lastCluster] < FAT16_BAD)
    lastCluster = fatTable[lastCluster];
```

追加写分两种情况：

1. **最后一个簇有剩余空间**（`fileSize % 512 != 0`）：先读出该簇对应扇区，把新数据复制到偏移 `fileSize % 512` 处，再写回扇区。

写完后更新目录项并同步 FAT：

```cpp
entry.fileSize += size;
writeDirEntry(idx, &entry);
syncFAT();
```

### 3.2 磁盘空间统计

**接口定义：**

```cpp
int FAT16::getFileClusterCount(const char *name);
float FAT16::getFragmentation();
```

**实现思路：**

**文件簇数统计（`getFileClusterCount()`）：** 从 `firstCluster` 开始沿 FAT 链遍历计数：

```cpp
while (cluster >= 2 && cluster < FAT16_BAD)
{
    count++;
    cluster = fatTable[cluster];
}
```

空文件返回 0，文件不存在返回 -1。

```cpp
if (next != current + 1)
    fragmentedLinks++;
```

```
碎片率 = fragmentedLinks / totalLinks
```

若无多簇文件（`totalLinks == 0`），返回 0。

- 跳过已被占的簇 7、8（tail.bin）。
- 分配空闲簇 9、10。

#### 4.3.1 输出验证与优化分析

结合 4.3 的实现，对 1500 字节文件的普通读写 vs 优化读写进行定量对比：

**（1）文件大小与簇数：** 1500 字节需要 `ceil(1500 / 512) = 3` 个簇。Step 4 中 `normal.bin` 从簇 2 开始，`opt.bin` 从簇 5 开始，各占 3 簇。Step 5 中 Used clusters = 6 = 3 + 3，簇数一致。

**（2）普通写 vs 优化写 — 命令数与 I/O 对比：**

| 指标 | 普通写 | 优化写 | 比值 |
|:---|:---:|:---:|:---:|
| ATA 命令数 | 39 | 1 | 39:1 |
| 16-bit Word I/O | 9984 | 768 | 13:1 |

普通写产生 39 条 ATA 命令，9984 word I/O = 9984/256 = 39 扇区。每次写操作包括：`selectSector` 设置扇区地址（产生额外命令开销）、数据扇区写入、FAT 表写回、目录项写回。每扇区独立写意味着每次都执行完整的 ATA PIO 协议循环：`waitReady()` → `selectSector(lba, 1)` → 发 WRITE 命令（`0x30`）→ 等 DRQ → 256 次 word I/O。3 个数据扇区叠加 FAT 和目录项操作，总计 39 次命令往返。

优化写仅 1 条命令、768 word I/O = 768/256 = 3 扇区（恰好 3 个数据扇区）。优化写将连续的 3 个数据扇区合并为一次多扇区写：`selectSector(lba, 3)` 设置扇区计数为 3，随后一次性写入 3×256 = 768 word。FAT 表更新和目录项写回被集中处理，大幅削减了 `selectSector` 和命令发送的协议开销，从 39 降至 1。

**（3）普通读 vs 优化读 — 对比：**

| 指标 | 普通读 | 优化读 | 比值 |
|:---|:---:|:---:|:---:|
| ATA 命令数 | 5 | 4 | 1.25:1 |
| 16-bit Word I/O | 1280 | 1536 | 0.83:1 |

普通读 5 条命令、1280 word I/O = 5 个独立扇区的读取量（含 3 个数据扇区 + FAT 链遍历中的 FAT 表读取）。优化读 4 条命令、1536 word I/O = 6 个扇区的传输量——优化读在批量合并策略下读取的数据量微增（可能额外包含了相邻元数据扇区的合并读取），但命令数从 5 降至 4，说明至少减少了一次 `selectSector` + 命令的往返。

**（4）优化原理总结：** 普通读写对每个扇区执行一次完整的 ATA PIO 协议循环，N 个扇区 = N 次循环。优化读写通过 `selectSector(lba, N)` 批量设置扇区计数，然后一条命令后连续执行 N×256 次 word I/O。协议开销从 O(N) 降至 O(1)。

**（5）内容正确性验证：** Step 3 中普通读成功读取 1500 字节，Step 4 中优化读也成功读取 1500 字节，`content check first/last ASCII: 65 82`（即 `'A'` 和 `'R'`），内容两端正确，证明优化读写未引入数据错误。
