### 2.2 Arena 分配器设计

**实现思路：**

Arena 分配器将一页内存（4096 字节）划分为多个固定大小的内存块，通过双向链表管理空闲块。设计包含以下核心数据结构：

| 元素 | 说明 |
|------|------|
| `Arena` | 位于每页头部（`sizeof(Arena) = 8` 字节），记录块类型 `type` 和空闲块计数 `counter` |
| `MemoryBlockListItem` | 空闲块链表节点，含 `previous` / `next` 前后指针 |
| `arenaSize[MEM_BLOCK_TYPES]` | 7 种块大小：16, 32, 64, 128, 256, 512, 1024（2 的幂） |
| `arenas[MEM_BLOCK_TYPES]` | 7 个空闲链表头指针，分别管理对应尺寸的空闲块 |
| `ARENA_MORE` | 特殊类型，用于 size > 1024 的大块分配 |

```cpp
enum ArenaType {
    ARENA_16, ARENA_32, ARENA_64, ARENA_128,
    ARENA_256, ARENA_512, ARENA_1024, ARENA_MORE
};

struct Arena {
    ArenaType type;
    int counter;
};

struct MemoryBlockListItem {
    MemoryBlockListItem *previous;
    MemoryBlockListItem *next;
};
```

**`getNewArena()` — 新页初始化：** 当某个空闲链表为空时，调用 `memoryManager.allocatePages()` 分配一页（4096 字节），将页开头置为 `Arena` 元信息，剩余空间按块大小切分为 `blockCount` 个空闲块，全部链入对应 `arenas[index]` 链表：

```cpp
bool ByteMemoryManager::getNewArena(int index) {
    int page = memoryManager.allocatePages(poolType, 1);
    Arena *arena = (Arena *)page;
    arena->type = (ArenaType)index;
    int blockCount = (PAGE_SIZE - sizeof(Arena)) / arenaSize[index];
    arena->counter = blockCount;

    int address = page + sizeof(Arena);
    for (int i = 0; i < blockCount; ++i) {
        MemoryBlockListItem *current =
            (MemoryBlockListItem *)(address + i * arenaSize[index]);
        current->previous = previous;
        current->next = nullptr;
        if (previous) previous->next = current;
        previous = current;
    }
    arenas[index] = (MemoryBlockListItem *)address;
    return true;
}
```

**结果分析：**

| Arena 类型 | 块大小 | 单页可分配块数 | 每页有效数据占比 |
|-----------|--------|--------------|----------------|
| ARENA_16 | 16 B | 255 | 99.6% |
| ARENA_32 | 32 B | 127 | 99.2% |
| ARENA_64 | 64 B | 63 | 98.4% |
| ARENA_128 | 128 B | 31 | 96.9% |
| ARENA_256 | 256 B | 15 | 93.8% |
| ARENA_512 | 512 B | 7 | 87.5% |
| ARENA_1024 | 1024 B | 3 | 75.0% |

页面头部仅占 8 字节（`sizeof(Arena)`），利用率很高。小块的内部碎片最大约为块大小的一半（如申请 17 字节分配 32 字节块，浪费 15 字节），是固定大小块分配的固有取舍。

### 2.3 分配与释放流程

#### 2.3.1 `allocate()` — 分配

**实现思路：**

```cpp
void *ByteMemoryManager::allocate(int size) {
    if (size <= 0) return nullptr;

    // 1. 确定分配级别
    int index = 0;
    while (index < MEM_BLOCK_TYPES && arenaSize[index] < size) ++index;

    // 2. 大块走 ARENA_MORE 整页分配
    if (index == MEM_BLOCK_TYPES) {
        int pageAmount = (size + sizeof(Arena) + PAGE_SIZE - 1) / PAGE_SIZE;
        int page = memoryManager.allocatePages(poolType, pageAmount);
        Arena *arena = (Arena *)page;
        arena->type = ARENA_MORE;
        arena->counter = pageAmount;
        return (void *)(page + sizeof(Arena));
    }

    // 3. 小块从空闲链表取头节点
    if (!arenas[index] && !getNewArena(index)) return nullptr;
    MemoryBlockListItem *item = arenas[index];
    arenas[index] = item->next;
    if (arenas[index]) arenas[index]->previous = nullptr;

    Arena *arena = (Arena *)((int)item & 0xfffff000);
    --arena->counter;
    return item;
}
```

**核心机制分析：**

- **小块分配**：计算满足 size 的最小块级别，从对应链表中取头节点。若链表空则调用 `getNewArena()` 分配新页。
- **大块分配**（`size > 1024`）：`index == MEM_BLOCK_TYPES`，按页数分配连续物理页，`Arena` 头记录 `ARENA_MORE` 类型，`counter` 表示分配的页数，用户数据从 `page + sizeof(Arena)` 开始。
- **地址池选择**：通过 `pcb->pageDirectoryAddress` 是否为 0 判断内核态 / 用户态，选择对应的地址池。

#### 2.3.2 `release()` — 释放

**实现思路：**

```cpp
void ByteMemoryManager::release(void *address) {
    if (!address) return;

    Arena *arena = (Arena *)((int)address & 0xfffff000);

    // 1. 大块直接释放 counter 页
    if (arena->type == ARENA_MORE) {
        memoryManager.releasePages(poolType, (int)arena, arena->counter);
        return;
    }

    // 2. 小块插回链表头部，counter++
    MemoryBlockListItem *item = (MemoryBlockListItem *)address;
    int type = (int)arena->type;
    item->previous = nullptr;
    item->next = arenas[type];
    if (item->next) item->next->previous = item;
    arenas[type] = item;
    ++arena->counter;

    // 3. 若整页空闲，从链表移除该页所有块并释放页面
    int totalBlocks = (PAGE_SIZE - sizeof(Arena)) / arenaSize[type];
    if (arena->counter != totalBlocks) return;

    MemoryBlockListItem *current = arenas[type];
    while (current) {
        MemoryBlockListItem *next = current->next;
        if ((int)arena == ((int)current & 0xfffff000)) {
            if (current->previous)
                current->previous->next = current->next;
            else
                arenas[type] = current->next;
            if (current->next)
                current->next->previous = current->previous;
        }
        current = next;
    }
    memoryManager.releasePages(poolType, (int)arena, 1);
}
```

**核心机制分析：**

- **定位 Arena 头**：通过 `(int)address & 0xfffff000` 获取所属页基址，直接读取 `Arena` 元信息。
- **小块归还**：插入空闲链表头部（O(1)），`counter++`。当 `counter == totalBlocks`（该页所有块都已归还）时，遍历链表将该页所有块节点从链表中移除，调用 `releasePages()` 归还该页给内存管理器，实现 **Arena 页回收**。
- **大块释放**：直接释放 `arena->counter` 页。

**结果分析：**

- 空闲链表头插入 O(1)，分配取头 O(1)；整页回收需要遍历链表移除属于该页的节点，复杂度 O(n)，但仅在 counter 满载时才触发。
- 通过 `counter` 计数实现精确的整页回收，避免了内存泄漏。

### 2.4 realloc 扩展

**实现思路：**

`realloc` 实现了四个分支语义：

```cpp
void *ByteMemoryManager::reallocate(void *address, int newSize) {
    // 1. ptr == nullptr → 等价 malloc
    if (!address) return allocate(newSize);

    // 2. newSize <= 0 → 等价 free，返回 nullptr
    if (newSize <= 0) {
        release(address);
        return nullptr;
    }

    // 3. newSize <= oldCapacity → 原地返回
    int oldCapacity = getBlockCapacity(address);
    if (newSize <= oldCapacity) return address;

    // 4. newSize > oldCapacity → 分配新块 → 复制 → 释放旧块
    void *newAddress = allocate(newSize);
    if (!newAddress) return nullptr;

    int copySize = oldCapacity < newSize ? oldCapacity : newSize;
    memcpy(address, newAddress, copySize);
    release(address);
    return newAddress;
}
```

`getBlockCapacity()` 返回指针所指内存块的容量：

```cpp
int ByteMemoryManager::getBlockCapacity(void *address) {
    if (!address) return 0;
    Arena *arena = (Arena *)((int)address & 0xfffff000);
    if (arena->type == ARENA_MORE)
        return arena->counter * PAGE_SIZE - sizeof(Arena);
    return arenaSize[(int)arena->type];
}
```

**结果分析：**

- **扩大**（如 32B → 2000B）：从 ARENA_32 迁移到 ARENA_MORE，分配新的 2000 字节空间，`memcpy` 复制 32 字节旧数据，释放旧块。
- **缩小**（如 512B → 64B）：新大小 ≤ 512B 容量，直接返回原地址。
- **边界**：`nullptr` 等价 `malloc`，`size <= 0` 等价 `free` 并返回 `nullptr`。

### 2.5 系统调用封装

**实现思路：**

新增三个系统调用，系统调用号为 6（`malloc`）、7（`free`）、8（`realloc`）：

```cpp
systemService.setSystemCall(6, (int)syscall_malloc);
systemService.setSystemCall(7, (int)syscall_free);
systemService.setSystemCall(8, (int)syscall_realloc);
```

`syscall_malloc` / `syscall_free` / `syscall_realloc` 统一通过以下逻辑区分内核态和用户态：

```cpp
void *syscall_malloc(int size) {
    PCB *pcb = programManager.running;
    if (pcb && pcb->pageDirectoryAddress)
        return pcb->byteMemoryManager.allocate(size);
    return kernelByteMemoryManager.allocate(size);
}
```

- **用户进程**：`pcb->pageDirectoryAddress != 0`，使用 PCB 内嵌的 `byteMemoryManager`，分配时使用用户地址池。
- **内核线程**：使用全局 `kernelByteMemoryManager`，分配时使用内核地址池。

`PCB` 结构体新增 `ByteMemoryManager` 成员，`fork()` 时通过 `child->byteMemoryManager = parent->byteMemoryManager` 复制。

**结果分析：**

- 每个用户进程拥有独立的 `byteMemoryManager`，进程间内存分配互不干扰。
- 内核 `kernelByteMemoryManager` 独立于用户进程，保证内核与用户态的隔离。

## 实验总结

本次 Lab10 Project 2 基于 Lab9 代码扩展，实现了以下功能：

1. **Arena 分配器**：7 种固定大小块（16B ~ 1024B），每页头部嵌入 `Arena` 元信息（`type` + `counter`），空闲块通过双向链表管理。分配 O(1) 取链表头，释放 O(1) 插回链表头。`counter` 达到满值时触发链表遍历 → 整页回收，归还给内存管理器。

2. **大块分配（ARENA_MORE）**：`size > 1024` 时按页数分配连续物理页，`counter` 记录页数，释放时一次性归还。

3. **realloc 扩展**：实现四分支语义 — `nullptr` 等价 `malloc`、`size <= 0` 等价 `free`、新大小 ≤ 原容量原地返回、新大小 > 原容量分配新块复制后释放旧块。

4. **系统调用与进程隔离**：系统调用号 6/7/8，PCB 内嵌 `ByteMemoryManager`。用户进程与内核使用不同的 `byteMemoryManager` 实例，`fork()` 时复制。

5. **测试验证**：14 个测试用例全面覆盖小块、大块、复用、整页回收、realloc 各分支及边界语义，全部通过。
