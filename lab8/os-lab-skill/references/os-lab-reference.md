## Lab1：Linux 内核与基础环境

- Linux 内核编译常用流程：`make i386_defconfig`、`make menuconfig`、`make -j$(nproc)`。
- QEMU 调试常用参数：`-s -S` 表示开启 gdbstub 并在启动后暂停；GDB 使用 `target remote :1234` 连接。
- `start_kernel` 是 Linux 内核启动主路径中的关键函数；若 GDB 无法显示源码行号，常见原因是未启用 debug info。
- initramfs/BusyBox 用于构造极简根文件系统；常见流程是准备目录、放入 BusyBox、创建 `init`、用 `cpio` 打包。
- `/proc` 是内核提供的虚拟文件系统；`/proc/cpuinfo`、`/proc/meminfo`、`/proc/modules` 可用于观察系统状态。
- `dmesg` 用于查看内核日志；BusyBox 环境中通常没有 `journalctl`，优先使用 `dmesg`。
- 内核模块实验通常包括 `insmod`、`lsmod`、`rmmod` 和 `dmesg` 验证。

## Lab2：MBR、实模式与汇编

- MBR 被 BIOS 加载到物理地址 `0x7C00`，大小通常为 512 字节，末尾签名为 `0x55AA`。
- 实模式物理地址公式：`物理地址 = 段寄存器值 << 4 + 偏移地址`，最大寻址空间约 1MB。
- BIOS `int 10h` 常用于文本输出、光标位置读取和光标移动；`int 16h` 常用于键盘输入。
- 常用寄存器：`eax/ebx/ecx/edx/esi/edi/ebp/esp`，段寄存器 `cs/ds/ss/es/fs/gs`，指令指针 `eip`，标志寄存器 `eflags`。
- 标志位分析常涉及 `ZF`、`CF`、`SF`、`OF`、`IF`、`DF`。
- 汇编报告要说明循环、分支、函数调用、栈使用和寄存器保护。

## Lab3：磁盘加载与保护模式

- CHS 与 LBA 的关系可用磁头数、每磁道扇区数推导；报告中应写出转换公式和代入过程。
- 保护模式依赖 GDT；段描述符是 8 字节结构，包含基址、界限和属性。
- `GDTR` 保存 GDT 的基地址和界限；段选择子提供 GDT 索引、TI 位和 RPL。
- 平坦模型下段基址通常为 0，逻辑地址和线性地址近似相同。
- 进入保护模式通常涉及加载 GDT、设置 `CR0.PE`、远跳转刷新流水线并切换到 32 位代码段。
- 分析 hex dump 时，将内存字节和段描述符字段对应起来，再与手工解析结果验证。

## Lab4：混合编程与中断

- C/C++ 与汇编互调时要明确调用约定、参数传递、栈平衡和符号名链接问题。
- C++ 调用汇编函数或汇编调用 C++ 函数时，必要时使用 `extern "C"` 防止名称修饰不一致。
- VGA 文本模式显存通常从 `0xB8000` 开始，每个字符单元 2 字节：字符 ASCII + 属性字节。
- IDT 用于中断和异常分发；中断入口需要保存现场、调用 C/C++ 处理函数、发送 EOI、恢复现场。
- 缺页异常可通过访问未映射地址触发；`CR2` 保存导致 page fault 的线性地址。
- PIT 8253/8254 常用输入频率为 `1193182 Hz`，计数值约为 `1193182 / 目标频率`。
- 键盘中断通常从端口 `0x60` 读取扫描码；`scan & 0x80` 可区分按下码和释放码。

## Lab5：内核线程与调度

- `printf` 实现重点：可变参数解析、格式字符处理、缓冲区输出和 VGA 打印。
- 线程实现重点：线程控制块、栈初始化、就绪队列、状态切换和首次线程启动。
- 上下文切换分析应说明寄存器保存/恢复、栈指针切换和返回路径。
- RR 调度优点是简单公平；缺点是无法区分任务重要性。
- 优先级调度能提高高优先级任务响应；缺点是可能导致低优先级线程饥饿或优先级反转。
- `thread_sleep`/`thread_wakeup` 报告要写清楚阻塞状态、唤醒条件和调度队列变化。

## Lab6：并发与同步

- 自旋锁适合极短临界区；缺点是忙等待浪费 CPU，并可能带来公平性和缓存一致性问题。
- `xchg` 常用于原子交换；`lock cmpxchg` 可实现 CAS，失败时通常减少无效写入。
- 信号量 `P` 操作申请资源，`V` 操作释放资源并唤醒等待线程。
- MESA 唤醒模型中，被唤醒线程只进入就绪队列，不立即执行，所以等待条件必须在循环中重新检查。
- 生产者-消费者报告要关注 `buffer`、`in`、`out`、`count` 是否保持一致，以及是否出现溢出、丢失或重复消费。
- 读者-写者问题要说明读者优先、写者优先或公平策略，以及是否可能饥饿。
- 死锁四个必要条件：互斥、占有并等待、不可抢占、循环等待。
- 哲学家就餐可通过限制同时拿筷子人数、资源有序申请或破坏循环等待来避免死锁。
- 管程将共享数据、互斥锁和条件变量封装在一起；条件变量用于 `wait/signal` 协调状态变化。

## Lab7：内存管理与分页

- `BitMap -> AddressPool -> MemoryManager` 可描述为三层：位图记录页使用状态，地址池管理连续页范围，内存管理器协调内核/用户物理池和虚拟池。
- 物理页分配报告要展示分配起始地址、释放后复用情况，以及位图如何变化。
- 开启分页常见三步：初始化页目录表/页表，将页目录表物理地址写入 `CR3`，设置 `CR0.PG`。
- `directory[0]` 常用于低地址恒等映射；`directory[768]` 常用于把内核映射到 `0xC0000000` 高地址；`directory[1023]` 常用于递归映射页目录表本身。
- 递归映射公式，若自映射 PDE 下标为 `S`：
  - 页目录项 `i` 的虚拟地址：`(S << 22) + (S << 12) + i * 4`
  - 第 `i` 个页表中第 `j` 个 PTE 的虚拟地址：`(S << 22) + (i << 12) + j * 4`
- 若 `S = 1023`，页目录虚拟基址为 `0xFFFFF000`，页表窗口基址为 `0xFFC00000`。
- 虚拟页分配通常包括三步：分配连续虚拟页，为每个虚拟页分配物理页，建立 PDE/PTE 映射。
- QEMU Monitor 可用 `info mem` 查看映射，用 `xp 物理地址` 验证虚拟地址写入是否落到预期物理页。
